# T011: Clerk auth — middleware protection, sign-in/up pages, getUserId()

**Date:** 2026-08-11

## What was done

Put the whole app behind sign-in with Clerk (`@clerk/nextjs@^7.7.3`, Core 3):

1. **Added dependency**: `@clerk/nextjs@^7.7.3` to package.json.

2. **`proxy.ts`** (Next.js 16 renamed `middleware.ts` to `proxy.ts` — confirmed via
   `node_modules/next/dist/lib/constants.js` and a local build showing `ƒ Proxy (Middleware)`):
   `clerkMiddleware` with `createRouteMatcher(["/sign-in(.*)", "/sign-up(.*)"])` as the public
   route set; everything else calls `await auth.protect()`. Matcher config is the standard
   Clerk Next.js quickstart pattern (skips `_next` and static assets, always runs for `/api`).

3. **`app/layout.tsx`**: wrapped `{children}` in `<ClerkProvider>` inside `<body>`.

4. **`app/sign-in/[[...sign-in]]/page.tsx`** and **`app/sign-up/[[...sign-up]]/page.tsx`**:
   render `<SignIn />` / `<SignUp />` from `@clerk/nextjs`.

5. **`lib/api/auth.ts`**: `getUserId(): Promise<string>` wraps `const { userId } = await auth()`
   from `@clerk/nextjs/server` and throws a typed `UnauthorizedError` when `userId` is null. This
   is the single entry point later API routes will use for identity — never call Clerk's `auth()`
   directly from a route.

6. **CI** (`.github/workflows/ci.yml`): added `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY:
   pk_test_Y2xlcmsuZXhhbXBsZS5jb20k` (base64 of `clerk.example.com$`, prefixed `pk_test_`, no
   padding) to the `Build` step's `env:`. This is a well-formed dummy test key, not a secret.

7. `.env.example` already listed `CLERK_SECRET_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`,
   `NEXT_PUBLIC_CLERK_SIGN_IN_URL`, `NEXT_PUBLIC_CLERK_SIGN_UP_URL` — no change needed.
