# T042 — Compose Panels from the existing timer/log components

## 2026-08-11

### What was done

`components/Panels.tsx` was a 14-line placeholder shell (T041). This task wires the
already-built, already-tested components into it — no new components, no new timer logic.

- `Panels` is now a client component that calls `useTimer()` exactly once and passes the
  resulting state down to every child, so the dial, jotter, control bar, recap bar, overlays
  and vine all observe the same timer instance.
- Left panel: `Dial` (which already renders the phrase block), `BulletJotter`, `PickerStrip`,
  `ControlBar`, `RecapBar`, with `ChimeOverlay` shown when `mode === "chime"` and
  `AwayOverlay` shown when `mode === "away"`.
- Right panel: `Vine`, fed the same `timerState` (it already owns the day/grid toggle,
  settings panel, and entry editing).
- `components/Panels.module.css`: added `position: relative` to `.leftPanel` so the
  chime/away overlays (`position: absolute; inset: 0`) cover the timer panel rather than the
  viewport. Existing grid/responsive/testid rules from T027/T028/T041 left untouched.
- `lib/client/useTimer.ts`: `AwayOverlay` requires `awayKind`/`awaySince`, but the client
  state never carried them (only `awayElapsedSeconds`, tracked locally since the server
  payload doesn't include away metadata). Extended `ClientState`/`toClientState` with
  `awayKind`/`awaySince`, populated the same way `awayElapsedSeconds` already is: captured
  locally in the client (`awayKindEntered`, reusing the existing `awayEnteredAt` local
  timestamp) at the moment `awayStart(kind)` is called, and cleared when the mode leaves
  "away". This is local client bookkeeping, not new engine/business logic — the server-side
  timer engine and API payload are unchanged (and out of this task's scope).

### Checks run

- `npm test` — 523/523 tests pass, including new `components/Panels.test.tsx` assertions that
  the composed `Panels` renders the dial (svg), bullet jotter, picker strip, control bar, and
  the vine's day view (verifies the panels are no longer empty placeholders).
- `npm run format:check` — clean.
- `npm run lint` — clean.
- `npm run build` — succeeds (Next.js production build + TypeScript check).

### What remains

Nothing outstanding for this task. A pre-existing gap: the server-side `StatePayload` never
carried `awayKind`/`awaySince`, so on a hard page reload while already in "away" mode, the
overlay won't have real away-kind/since data until the user re-triggers `awayStart` — fixing
that would mean touching `lib/api/timer-state.ts`, which is outside this task's scope
(`components/**`, `app/**`, `lib/client/**` only).
