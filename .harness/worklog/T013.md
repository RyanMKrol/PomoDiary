# T013 Worklog

## 2026-08-11

### Summary
Built the entries API for reading and patching entries with full test coverage against PGlite.

### Implementation

**lib/api/entries.ts**
- `getEntriesHandler`: GET /api/entries?from=<ms>&to=<ms>
  - Validates both params required, are integers, from < to, span ≤ 31 days
  - Returns entries with from inside [from, to), newest-first ordering
  - All range-queries delegated to listEntriesForRange store function
- `patchEntryHandler`: PATCH /api/entries/[id]
  - Verifies entry exists and belongs to authenticated user (404 if not)
  - Validates patch with entryPatchParsedSchema (custom schema that lets store handle CapError for 422)
  - Returns updated entry or 422 on cap violation

**app/api/entries/route.ts**
- GET handler using handleRoute for auth/rate-limit/error mapping

**app/api/entries/[id]/route.ts**
- PATCH handler that parses body inside handleRoute so BadRequestError is caught and mapped to 400

**entryPatchParsedSchema** (lib/api/entries.ts)
- Custom schema that validates enum values but not bullet sizes
- Lets the store's validateBullets throw CapError for 422 responses (not 400 from schema)
- Matches spec requirement: "422 on cap violation"

### Tests

**app/api/entries/route.test.ts** (14 tests)
- Authentication: 401 when unauthenticated, 429 when rate limited
- Validation: missing params, invalid types, from >= to, span > 31 days all return 400
- Range queries: [from, to) bounds exclusive at to/inclusive at from, newest-first ordering
- User scoping: returns only authenticated user's entries
- Empty result handling

**app/api/entries/[id]/route.test.ts** (14 tests)
- Authentication: 401, 429 same as GET
- Validation: invalid JSON (400), empty patch (400)
- Entry access: 404 for nonexistent entry, 404 for other user's entry
- Patches: bullets, tag, feel, intent individually and together
- Cap violations: 422 for too many bullets, 422 for bullet char limit
- Field preservation: unpatched fields remain unchanged
