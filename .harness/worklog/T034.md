## 2026-08-11

Built the Clerk `user.deleted` webhook that purges a departing user's data from Neon.

What I did:

- Added `svix` as a dependency.
- `lib/db/purge.ts`: `purgeUser(db, userId)` deletes the user's rows from `entries`,
  `timerState`, and `userSettings`, returning per-table counts. Since the neon-http driver
  has no interactive transaction support (it's a stateless HTTP client — `db.transaction()`
  throws at runtime), it uses `db.batch()` for atomicity against the real database and falls
  back to `db.transaction()` against PGlite in tests (which supports transactions but not
  `batch()`).
- `app/api/webhooks/clerk/route.ts`: `POST` handler split into an exported
  `handleClerkWebhook(req, db)` (for testing with an injected PGlite db) and a thin `POST`
  wrapper that calls it with `getDb()`. Reads `CLERK_WEBHOOK_SIGNING_SECRET` from
  `process.env` at request time (503 if unset), verifies the raw body against the svix
  headers with the `svix` package (400 on failure), purges on `user.deleted`, no-ops with 200
  on any other event type.
- `proxy.ts`: added `/api/webhooks(.*)` to the public-route matcher alongside sign-in/sign-up.
- `.env.example`: added `CLERK_WEBHOOK_SIGNING_SECRET` (name only — value lives in Vercel,
  provisioned per the T032 runbook).
- Tests: `lib/db/purge.test.ts` covers purging a user's rows across all three tables while
  leaving another user's rows intact, plus the zero-rows case. `app/api/webhooks/clerk/route.test.ts`
  drives the real svix `Webhook` class to sign a test payload and asserts 503 (no secret), 400
  (tampered payload vs. its signature), 200 + purge (validly-signed `user.deleted`), and 200
  no-op (other event types).

Checks run: `npm test` (165 passed), `npm run format:check`, `npm run lint`, `npm run build` —
all green.

What remains: the Clerk dashboard webhook + Vercel env var setup itself is the T032 deploy
runbook's job, not this task's.
