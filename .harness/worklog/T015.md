# T015 — Client timer hook: server reconciliation + 1s tick

## 2026-08-11

Built the client-side timer brain in `lib/client/`:

- `createTimerClient(fetchImpl?)` (in `lib/client/useTimer.ts`) is a plain, framework-free
  controller: on `start()` it `GET`s `/api/state` (with `todayStart`/`todayEnd` query params
  computed locally so the response includes today's entry count), holds the derived state +
  settings + `hoursToday`, and runs a 1s `setInterval` tick.
- The tick rebuilds a minimal shadow of the engine's `TimerState` from each server payload
  (`reconstructShadow`) and re-derives it every second with `deriveNow` (imported from
  `lib/timer/engine`, never reimplemented) to count down locally and detect the wall-clock
  crossing into chime. On a local chime flip it updates state, fires the chime event once, and
  triggers a `GET /api/state` refetch so the server-derived truth reconciles (the "ringNow
  equivalent read" from the spec). While away, elapsed time is tracked from the client-observed
  entry-into-away moment (the state payload doesn't expose `awaySince`).
- `dispatch`-style actions (`pause`, `resume`, `restart`, `ringNow`, `acknowledge`, `log`, `skip`,
  `awayStart`, `awayReturn`) `POST /api/timer` and replace local state with the response; on a
  failed POST they fall back to a `GET /api/state` refetch (server wins).
- `updateDraft` applies the patch locally at once and debounces the `draftUpdate` POST (800ms
  trailing, merging patches from rapid calls into a single POST); `log`, `skip`, and `awayStart`
  flush any pending draft first.
- `updateSettings` PATCHes `/api/settings` and merges the returned settings into state.
- `useTimer(options?: { onChime })` is the thin React hook wrapping the controller via
  `useState`/`useEffect`, exposing the derived state plus the typed action wrappers and the
  `onChime` callback for T021/T022.

No jsdom/@testing-library dependency is installed in this repo, so the hook itself is a small,
directly-reviewable wrapper; all state-machine behaviour lives in `createTimerClient` and the
colocated pure helpers (`reconstructShadow`, `toClientState`, `applyDraftPatchLocally`,
`todayBoundsFor`), which are fully unit-tested in `lib/client/useTimer.test.ts` using
`vi.useFakeTimers()` and a fetch mock built on the real `dispatch`/`buildStatePayload` engine
functions (so the simulated server behaves exactly like the real routes, without a DB or jsdom).

Tests cover: initial load populating state; the 1s tick counting down; crossing the session
boundary flipping to chime exactly once (and not re-firing on later ticks) plus a server
reconcile refetch; a dispatched action (`pause`) posting and applying the response; rapid draft
updates coalescing into a single debounced POST while still applying locally at once; `log`
flushing a pending draft first; and a failed POST falling back to a state refetch.
