# T036 Worklog

## 2026-08-11

Built data export endpoint that allows users to download all their logged entries as JSON.

### Implementation

1. **lib/db/entries.store.ts**: Added `listAllEntries(db, userId)` function that retrieves all entries for a user in chronological order (oldest first).

2. **lib/db/timer-state.store.ts** & **lib/db/entries.store.ts**: Added `Db` type union to support both test and production databases, allowing functions to work with both `TestDb` and `NeonHttpDatabase`.

3. **lib/api/route-handler.ts**: Created shared route helper that handles:
   - Authentication with `getUserId()`
   - Rate limiting using write-tier limiter
   - Error mapping for `UnauthorizedError` → 401
   - Rate limit exceeded → 429 with Retry-After header

4. **app/api/export/route.ts**: Implemented GET endpoint that:
   - Calls auth/rate-limit via shared handler
   - Fetches user's entries (oldest-first) and settings
   - Returns JSON with `exportedAt`, `userId`, `settings`, and `entries` properties
   - Sets `Content-Disposition: attachment; filename="pomodiary-export.json"` header

5. **app/api/export/route.test.ts**: Comprehensive test suite covering:
   - 401 response when unauthenticated
   - 429 response when rate limited (with Retry-After header)
   - Entries returned in chronological order (oldest first)
   - Only user's own entries are exported (isolation verified)
   - User settings included in export
   - JSON structure and content-disposition header correct
