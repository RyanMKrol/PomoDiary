# T006: Drizzle schema, Neon client, migrations, PGlite test harness

## Build log — 2026-08-11

Added the persistence foundation for entries, per-user timer state, and settings.

### What was built:
- Deps: `drizzle-orm`, `@neondatabase/serverless` (dependencies); `drizzle-kit`,
  `@electric-sql/pglite` (devDependencies).
- `lib/db/schema.ts` — three tables, every row keyed by Clerk `userId`:
  - `entries`: uuid id, userId, from/to (timestamptz), tag, feel, intent (nullable), bullets
    (jsonb `string[]`), createdAt. Composite index on `(userId, from)`.
  - `timerState`: userId primary key, mode, hourStart, pausedRemaining, chimeFrom/chimeTo,
    awayKind/awaySince, draftBullets (jsonb `string[]`), draftTag/draftFeel/draftIntent,
    phraseIdx, updatedAt.
  - `userSettings`: userId primary key, sessionMinutes (default 60), soundOn (default true),
    chimeVolume (default 0.8), pauseAfterLog (default false).
- `lib/db/index.ts` — `getDb()`, a plain memoizing function (not a Proxy). Constructs the
  `neon()` + `drizzle-orm/neon-http` client lazily on first call, so `next build` never
  evaluates it without `DATABASE_URL`. Throws immediately under `process.env.VITEST` so tests
  can never reach a real database.
- `lib/db/test-db.ts` — `createTestDb()` builds a Drizzle instance over an in-memory PGlite
  database and applies the committed `drizzle/` migrations. Throws if `DATABASE_URL` is set,
  so it can never accidentally point at a real database.
- `drizzle.config.ts` + generated `drizzle/0000_condemned_monster_badoon.sql` via
  `npx drizzle-kit generate`, committed. Added `db:generate` / `db:migrate` package scripts.
- Tests: `lib/db/index.test.ts` — migrations apply cleanly, an entry's `bullets` round-trips as
  `string[]`, `timerState` upsert (insert + update + insert-on-conflict) keeps one row per user,
  and `getDb()` throws under vitest.

### Verification (Definition of Done):
