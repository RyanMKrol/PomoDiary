# T028 Worklog

## 2026-08-11

### What was done

Accessibility pass across the components the designer scoped as open work. Each
component was already unit-tested in isolation (nothing wires them into `app/page.tsx`
yet — that's a separate integration task), so the changes and their tests follow that
same self-contained pattern.

1. **Live region** (`components/LiveRegion.tsx`, new): a visually-hidden
   `aria-live="assertive"` region that watches `timerState.mode` and announces the
   three transitions — entering chime (`Time's ripe. {range}. Click anywhere to
   account for the hour.`), entering away (`Asleep since {time}` / `At work since
   {time}`, via separate `awayKind`/`awaySince` props since those aren't part of
   the public `ClientState`), and returning from away (`Back. {n} hours logged.`).
   `ChimeOverlay`'s button also got a matching `aria-label`.
2. **Grid cells** (`components/GridView.tsx`): each cell now has `role="img"` with
   `aria-label` equal to its existing `title`; each day row (already the sole
   interactive/focusable element in its row) gets an `aria-label` like
   "Today, 3 hours logged. Open day." (singular "hour" for count === 1).
3. **Bullet inputs** (`components/BulletJotter.tsx`): each input gets
   `aria-label="Bullet {n} for this hour"`; the list is wrapped in
   `role="group" aria-label="Bullets for this hour"`.
4. **Picker rows** (`components/PickerStrip.tsx`): the tag chip group, feel row, and
   intent row are each a labelled `role="group"`, and every option (chip/segment)
   carries `aria-pressed` reflecting selection — all three rows support toggle-off,
   so `aria-pressed` on a button is the correct semantic (not `role="radio"`, which
   can't represent deselection).
5. **Reduced motion** (`app/globals.css`): a global
   `@media (prefers-reduced-motion: reduce)` rule forces
   `animation-duration: 0.01ms !important; animation-iteration-count: 1 !important`
   on every element, which suppresses `breathe`/`ringPulse`/`riseIn`/`wipeIn`/
   `barGrow`/`popDot` wherever they're used without touching ordinary CSS
   `transition`s (hover states etc. stay as they were). Also added a
   `.visually-hidden` utility class used by `LiveRegion`.
6. **Focus order**: `BulletJotter`'s existing "focus lands on the last bullet on
   entering recap" behaviour (from T017) already had a passing RTL test — left
   untouched, just confirmed still green. `Vine.tsx` now returns focus to the
   settings button (`ref` + `onClose` calling `.focus()`) when `SettingsPanel`
   closes, whether via outside click or the panel's own close path.

### Tests

Added/extended RTL suites: `LiveRegion.test.tsx` (new — all three transitions plus
the "no announcement on first render" case), `PickerStrip.test.tsx` (new — this
component previously had no test file; covers the three grouped roles and
`aria-pressed` states), plus accessibility `describe` blocks added to
`GridView.test.tsx` (cell role/aria-label, row aria-label incl. singular/plural),
`BulletJotter.test.tsx` (`getByLabelText` per bullet, grouped list),
`ChimeOverlay.test.tsx` (aria-label matches full copy), and `Vine.test.tsx` (focus
returns to the settings button on close). Added
`app/globals.reduced-motion.test.ts`, a node-env test that reads `globals.css`
directly and pins the reduced-motion media query, its `animation-*` overrides
(and that it does *not* touch `transition-duration`), and that the six keyframes
it's meant to suppress are still defined.
