# T017 Worklog

## 2026-08-11

### What was done

Created `components/BulletJotter.tsx` component for the scrolling list of bullet input fields with the following features:

1. **UI Layout**: Scroller region with heading, borderless inputs, and animated markers
   - Flex layout with min-height:0 for proper scrolling
   - 2px top rule with 32px side padding
   - Heading row showing context-dependent copy (running vs recap mode)
   - Bullet marker with popDot animation in active hue

2. **Key Handling**: Exact Enter/Backspace semantics from prototype
   - Enter: inserts empty bullet AFTER current index, never appends to end
   - Backspace on empty bullet: removes it and focuses previous
   - Backspace on non-empty or single bullet: does nothing
   - preventDefault() called to prevent form submission

3. **Focus Mechanics**: Deferred-focus pattern with ref array
   - Ref array kept in sync with bullet array via splice
   - pendingFocusIndex state tracks which input to focus after render
   - useEffect applies focus after state update (refs guaranteed to exist)
   - Recap mode focuses last bullet on enter (via isRecap initializer)

4. **Styling and Placeholders**
   - 8px square markers with popDot animation (0.35s cubic-bezier)
   - 17px/600/-0.015em borderless transparent input
   - 1px bottom hairline dividers
   - Index 0: "Jot it down while it's fresh…" (running) or "Wrote the pricing page copy" (recap)
   - Other indexes: "…"
   - Marker color follows active hue (draftTag or inferred tag, or #ec3013)

5. **Draft Syncing**: updateDraft callback for server sync
   - Called on every input change via onChange handler
   - Server debounces via T015's useTimer hook
   - Changes applied locally immediately for responsive UX

### Notes

The component integrates with:
- `useTimer()` via timerState prop (mode, draftBullets, draftTag)
- Tag inference via `inferTag()` from lib/domain
- Tag color via `tagColor()` from lib/domain
- CSS animations (popDot) defined in BulletJotter.module.css

The prototype ref mechanism (focus management via pendingFocusIndex) works correctly because React guarantees ref callbacks are called before effects, so refs are synchronized before focus is applied.

Component is self-contained and makes no assumptions about parent state management—all state updates flow through updateDraft callback.
