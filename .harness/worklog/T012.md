# T012: Timer state + settings API routes

**Date:** 2026-08-11

## What was done

Built the three thin server API routes for the timer, delegating all logic to `lib/api/`:

1. **`lib/api/timer-state.ts`** — shared conversions between the T008 engine's `TimerState`/
   `Settings` and the DB row shapes (`Date` <-> epoch ms, mode/awayKind casts), plus
   `loadOrCreateState` (creates `initialState(now)` and persists it on first touch),
   `loadSettings` (falls back to defaults without requiring a persisted row), and
   `buildStatePayload` (runs `deriveNow` and shapes the GET/POST response: mode,
   remainingSeconds, chime span, drafts, phraseIdx, settings, optional `count`).

2. **`app/api/state/route.ts`** + **`lib/api/state.ts`** — `GET`: reads optional
   `todayStart`/`todayEnd` query params, validates the span is ≤48h (client-supplied bounds
   per the timezone rule — the server never derives "today" itself), counts entries in that
   window when both are given, and returns the derived state + settings.

3. **`app/api/timer/route.ts`** + **`lib/api/timer.ts`** — `POST`: parses the body with
   `timerActionSchema`, loads state/settings, runs the T008 `dispatch` with `now =
   Date.now()`, persists the new state and any `entriesToInsert`, and returns the same
   derived-state shape as GET.

4. **`app/api/settings/route.ts`** + **`lib/api/settings.ts`** — `GET`/`PATCH`, the latter
   validating with `settingsPatchSchema`, upserting, and returning the new settings.

5. **`lib/api/route-handler.ts`** — added `BadRequestError` + `parseJsonBody()` (JSON parse +
   zod validation, 400 on failure) and mapped `CapError` (from `entries.store`) to 422 in the
   existing `handleRoute` catch block, alongside the existing 401/429 handling.

Each route file is a thin wire-up (auth/rate-limit via `handleRoute`, then delegate) well
under 40 lines.

## Tests

Added integration tests (vitest, in-process, importing route handlers directly with `Request`
objects), mocking Clerk auth, `lib/db`'s `getDb`, and `lib/ratelimit`, backed by the PGlite
test DB:

- `app/api/state/route.test.ts`: 401 unauthenticated, 429 rate-limited, first-touch creates
  initial state + default settings, entry count within `[todayStart, todayEnd)`, 400 on a
  >48h span.
- `app/api/timer/route.test.ts`: 401, 429, 400 on an invalid action body, and a full
  `ringNow` → `acknowledge` → `log` cycle that inserts an entry and resets the drafts.
- `app/api/settings/route.test.ts`: GET defaults, PATCH validation (400), PATCH round-trips a
  settings update.
