# T007 — Store modules for entries and timer state

## 2026-08-11

Built the complete data-access layer for entries and timer state, with enforced per-user storage caps.

### Implementation

1. **entries.store.ts** — Complete entry management:
   - `insertEntry()` and `insertEntries()` for single and batch inserts
   - `listEntriesForDay()` and `listEntriesForRange()` for querying entries (newest-first)
   - `updateEntry()` with field-level patching (tag, feel, intent, bullets only)
   - `countEntriesForDay()` for cap checking
   - `CapError` class for typed cap violations
   - Three enforced caps at the function layer:
     * Max 100 entries per user per UTC calendar day (abuse guard)
     * Max 30 bullets per entry
     * Max 500 characters per bullet

2. **timer-state.store.ts** — Timer and settings management:
   - `getTimerState()` / `upsertTimerState()` for per-user timer state
   - `getSettings()` / `upsertSettings()` for per-user settings with defaults
   - Defaults: 60-minute sessions, sound on, 0.8 volume, no pause-after-log

3. **Type safety**:
   - Created `TestDb` type export from `test-db.ts`
   - Used generic function signatures `<T extends TestDb>` instead of `any`
   - Exported `Entry`, `TimerState`, and `UserSettings` types for test assertions

4. **Tests** (29 tests, all passing):
   - Cross-user isolation verified (user A cannot read/write user B's entries)
   - Cap boundaries tested at edge cases (30 bullets ok, 31 throws; 500-char bullet ok, 501 throws; 100 entries ok, 101 throws)
   - Day/range queries validated across day boundaries
   - Update patching verified (only allowed fields modified, user scoping enforced)
   - Timer state upsert tested including away modes
   - Settings defaults and patching verified
   - All tests run hermetically on PGlite (zero prod DB access)

### Design notes

- Day cap uses UTC midnight boundaries (not user time), computed server-side on insert
- Query ranges use `>=` for start and `<` for end (includes start of day, excludes end)
- All insert/update operations return void; queries return typed results
- Settings patch upsert merges new values into existing row; missing keys preserve old values
