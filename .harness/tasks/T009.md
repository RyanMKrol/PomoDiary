## Overview

zod schemas for every API payload plus the shared limits constants — the validation wall that
keeps malformed or oversized input away from the stores and the DB.

## Do

1. Add dep `zod`.
2. Create `lib/validation/` exporting:
   - `LIMITS`: `MAX_BULLETS_PER_ENTRY = 30`, `MAX_BULLET_LENGTH = 500`,
     `MAX_ENTRIES_PER_DAY = 100`, `SESSION_MINUTES_MIN = 1`, `SESSION_MINUTES_MAX = 180`
     (single source of truth — T007's store caps should import these).
   - `bulletsSchema`: array of strings, each ≤ 500 chars, max 30 items.
   - `tagSchema`: one of the 8 `TAGS` labels, the 2 away tags, or `Unfiled` (import labels from
     `lib/domain` — never retype them). `feelSchema`: one of the 4 FEELS labels or `—`.
     `intentSchema`: `"yes" | "no" | null`.
   - `timerActionSchema`: discriminated union on `type` for pause, resume, restart, ringNow,
     acknowledge, log (payload: bullets/tag/feel/intent, tag/feel/intent nullable), skip,
     awayStart (kind: `sleep|work`), awayReturn, draftUpdate (partial drafts).
   - `settingsPatchSchema`: partial of `{ sessionMinutes (int, 1–180), soundOn (boolean),
     chimeVolume (0–1), pauseAfterLog (boolean) }`.
   - `entryPatchSchema`: partial of `{ bullets, tag, feel, intent }` with at least one key.
3. Unit tests: boundary accept/reject per schema (500 vs 501 chars, 30 vs 31 bullets, 1/180 vs
   0/181 minutes, unknown tag rejected, unknown action type rejected, `draftUpdate` with empty
   patch accepted or rejected per your choice — document which in the schema).

## Done when

`npm test` passes; every schema above exists and is exercised at its boundaries; tag/feel values
are derived from `lib/domain` constants, not retyped literals.
