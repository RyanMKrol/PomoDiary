## Overview

Take PomoDiary live: apply the database migrations to the production Neon database, switch
Clerk to a production instance, confirm the Vercel production deployment works end to end,
and smoke-test the real flow with a real account.

## Do

1. Migrations: `npx dotenv -e .env.local -- npm run db:migrate` (or set `DATABASE_URL` inline)
   against the production Neon database. Note for the future: any task that adds a migration
   needs this re-run — keep it in this runbook.
2. Clerk: in the Clerk dashboard create/enable the production instance for the Vercel
   production domain (`<project>.vercel.app` or a custom domain), update the production env
   vars on Vercel if the keys differ, and redeploy.
2b. If T034 (account-deletion webhook) is built: in the Clerk dashboard add a webhook
   endpoint pointing at `https://<production-domain>/api/webhooks/clerk` subscribed to
   `user.deleted`, copy its signing secret into the Vercel env as
   `CLERK_WEBHOOK_SIGNING_SECRET`, redeploy, and use Clerk's "send test event" to confirm a
   200.
3. Confirm the Vercel production deployment of `main` builds green and serves; sign up with a
   real account.
4. Smoke test on production: sign in → ring the dial → acknowledge → type a bullet containing
   `email` → confirm the suggestion reads like comms → log it → the entry appears in the vine
   and survives a reload; open the grid; flip a setting and reload to confirm it stuck; check
   a second browser/incognito session cannot see the first account's data.
5. Optional while you're there: attach a custom domain; enable Vercel's bot filtering
   defaults.

## Done when

The production URL serves the app behind sign-in; the smoke-test flow above passes including
the reload-persistence and cross-account isolation checks. Then mark done:
`.harness/scripts/mark-done.sh T032`.
