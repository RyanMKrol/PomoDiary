## Overview

A data-export endpoint: any signed-in user can download everything they've logged as JSON —
insurance against lock-in and a courtesy for future users.

## Do

1. `lib/db/entries.store.ts` (or a sibling): `listAllEntries(db, userId)` — every entry the
   user owns, oldest-first (chronological reads better in an export).
2. `GET /api/export` (`app/api/export/route.ts`): `getUserId()` → rate-limit with a STRICTER
   write-tier window (exports are heavy; reuse the `write` limiter) → respond with
   `{ exportedAt, userId, settings, entries: [...] }` as JSON, with
   `Content-Disposition: attachment; filename="pomodiary-export.json"` so the browser
   downloads it.
3. Reuse the shared route helper (auth/rate-limit/error mapping) — no logic in the route.
4. Tests (in-process, PGlite, mocked auth): export contains exactly the user's entries
   oldest-first plus their settings and none of another user's; the attachment header is
   set; rate-limit block → 429.

## Done when

`npm test` passes with the export suite; hitting `/api/export` signed in downloads a JSON
file with all your entries; another account's export excludes them.
