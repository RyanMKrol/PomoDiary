## Overview

Standard security headers for an external-facing app, served on every response via
`next.config.ts` — clickjacking, MIME-sniffing, referrer, and browser-feature hardening,
without breaking Clerk's sign-in flow.

## Do

1. In `next.config.ts`, add an async `headers()` returning, for `source: "/(.*)"`:
   - `X-Content-Type-Options: nosniff`
   - `X-Frame-Options: DENY` and `Content-Security-Policy: frame-ancestors 'none'`
   - `Referrer-Policy: strict-origin-when-cross-origin`
   - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
   Do NOT attempt a full `script-src` CSP in this task — Next.js inline scripts need nonces
   and Clerk loads cross-origin scripts; a broken CSP takes the whole app down. The
   frame-ancestors directive is the safe, high-value slice.
2. Add `test/security-headers.test.ts`: import the config and assert the headers array
   contains each name/value pair above for the catch-all source.
3. Verify against the running app: `npm run dev` (or the T029 harness if present), fetch `/`
   and confirm the headers are present on the response and sign-in still renders.

## Done when

`npm test` passes including the new header assertions; a `curl -sI` of the dev server shows
all five headers; the Clerk sign-in page still renders normally with the headers active.
