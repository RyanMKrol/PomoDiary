## Overview
Re-attempts the test-infrastructure half of T014, which the loop blocked on its first attempt because the builder had to touch tsconfig.json (type support for jest-dom/jsdom so tsc and the build stay green) and tsconfig.json was missing from the declared scope. This unit carries the corrected scope (tsconfig.json included) and is split out from the app-shell work so each piece is atomic.

## Do
Set up React Testing Library component testing on Vitest:

1. Add dev deps: `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`, `jsdom`.
2. In `vitest.config.ts`: set `environment: "jsdom"`, register `test/setup.ts` via `setupFiles`, and keep test discovery limited to `app/**`, `components/**`, `lib/**`, `test/**` (never `.harness/**` — the existing include list misses `components/**`; add it).
3. Create `test/setup.ts`: import `@testing-library/jest-dom/vitest` (loads the matchers) and stub `window.matchMedia` (return a minimal MediaQueryList-shaped object) so components using media queries render under jsdom.
4. Update `tsconfig.json` as needed so TypeScript knows the jest-dom matchers and jsdom globals (e.g. a `types` entry or equivalent) — `npm run build` and editor typechecking must stay green with the new matchers used in tests. You ARE allowed to edit tsconfig.json in this task; keep the existing `.harness` exclusion intact.
5. Existing node-environment tests in `test/` and `lib/` must keep passing — if a test needs node env (e.g. PGlite DB tests, security-headers), keep them working (per-file `// @vitest-environment node` or environmentMatchGlobs), do not break them by flipping the global environment.

## Done when
`npm test` passes and includes a new infra smoke test (e.g. `test/rtl-setup.test.tsx`) that: renders a trivial inline React component with RTL's `render`, asserts on it with a jest-dom matcher (`expect(...).toBeInTheDocument()`), and asserts `window.matchMedia("(min-width: 1px)")` is callable and returns an object with a `matches` boolean. All pre-existing tests (lib/time, lib/db PGlite tests, test/security-headers, test/smoke) still pass unchanged. `npm run build` succeeds with the jest-dom types configured.
