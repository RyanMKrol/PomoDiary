## Overview

Make the chime reach a user who is looking at another window: flip the page title and favicon
while the chime waits, and fire a system notification (with a permission prompt at a sensible
moment).

## Do

1. `lib/notify/` module:
   - `setChimeTitle(on: boolean)`: while a chime is unacknowledged, page title becomes
     `⏰ Time's ripe — PomoDiary` (restore the plain title on acknowledge).
   - Favicon swap: ship a second favicon (accent-red square variant) in `public/` and swap the
     `<link rel="icon">` href while chiming; restore after.
   - `requestNotifyPermission()`: call `Notification.requestPermission()` — trigger it from the
     first user interaction with the timer (e.g. first successful action dispatch), never on
     page load.
   - `notifyChime(fromTs, toTs)`: when permission is granted and the page is hidden
     (`document.visibilityState === "hidden"`), post a Notification titled `Time's ripe.` with
     body `{fmtClock(from)} – {fmtClock(to)} — come account for it`; clicking it focuses the
     window. No notification when the page is visible.
2. Wire to T015's chime event alongside the sound; clear title/favicon on `acknowledge`.
3. Guard everything for SSR (`typeof window`/`Notification` checks) — build must pass.
4. Tests (jsdom, Notification and visibility stubbed): title flips on and restores; favicon
   href swaps and restores; notification fires only when hidden+granted; permission requested
   only after an interaction, not on mount.

## Done when

`npm test` passes with the stubbed-notification suite; with the app chiming in a background
tab the title/favicon change and (when permitted) a system notification appears; nothing
prompts for permission on first page load.
