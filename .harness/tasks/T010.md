## Overview

Request rate limiting for the external-facing API, backed by Upstash Redis, built to fail OPEN
(allow, with a logged warning) when the Upstash env vars are absent so local dev and CI never
need Redis.

## Do

1. Add deps `@upstash/redis` and `@upstash/ratelimit`.
2. Create `lib/ratelimit/` exporting `checkRateLimit(key: string, kind: "read" | "write"):
   Promise<{ ok: boolean; retryAfterSeconds?: number }>`:
   - Lazy singleton Upstash client from `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`
     (never constructed at module top level — build must pass without env).
   - Sliding windows: writes 60/min per key, reads 120/min per key.
   - Missing env → return `{ ok: true }` and `console.warn` once per process (fail-open).
   - Redis errors → fail-open likewise (availability over strictness; log the error).
3. Key convention helper: `userKey(userId)` and `ipKey(ip)` (callers pass whichever they have).
4. Unit tests with the Upstash client mocked (`vi.mock`): allows under the limit, blocks over
   it with `retryAfterSeconds`, fail-open path when env is missing, fail-open on a thrown Redis
   error. No test may talk to real Redis.

## Done when

`npm test` passes with the mocked-limit, blocked, and both fail-open cases covered; `npm run
build` passes with no Upstash env set.
