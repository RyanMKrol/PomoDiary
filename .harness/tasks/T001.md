## Overview

Lay the minimal Next.js project skeleton and turn the Definition-of-Done tooling on. This is the
ONE task that defines the project-wide conventions (formatter, linter, test runner, CI) that gate
every later build, and its whole-repo tooling sweeps a tree that already vendors files the loop
must never touch. So a human sets it up once, by hand, rather than the loop. (`gate: needs-human`:
the loop skips this task and records `failed:blocked` until you mark it done.)

## Do

1. **Create a real, empty Next.js build.** Scaffold a TypeScript Next.js App Router project in the
   repo root (e.g. `npx create-next-app@latest . --ts --app`), keeping the existing `README.md`,
   `CLAUDE.md`, `.gitignore`, `.prettierignore`, and `.harness/` intact.
2. **Wire the DoD scripts.** In `package.json`, make these all exist and pass:
   - `npm run format:check` (Prettier check over the repo)
   - `npm run lint` (ESLint)
   - `npm test` (test runner; a passing empty suite is fine to start)
   - `npm run build` (`next build`)

   `.github/workflows/ci.yml` already runs exactly these; they must stay in lockstep with it and
   with `LOCAL_DOD` in `.harness/config/harness.env`.
3. **Exclude the harness from your own tooling (critical).** The whole-repo tools must not sweep
   the vendored harness tree or the harness-authored root prose:
   - `.prettierignore` already ships with `.harness/` and `CLAUDE.md`; keep it.
   - Add `.harness/**` to the ESLint flat-config `ignores`.
   - Scope test discovery so the runner does not pick up `.harness/dashboard/*.test.js`
     (`node --test` and jest recurse by default).
4. **Get it green.** Format, lint, test, and build pass locally, then push and confirm the CI
   workflow passes on `main`.

## Done when

CI is green on `main`; `npm run format:check`, `npm run lint`, `npm test`, and `npm run build` all
pass locally and match what `.github/workflows/ci.yml` runs; and the tooling ignores `.harness/**`
and the harness-authored root prose. Then mark this task done so its dependents unblock:
`.harness/scripts/mark-done.sh T001` (or the dashboard's "Mark done").
