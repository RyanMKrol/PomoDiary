## Overview

The read/edit API for the vine: entries for a selected day, the 10-day range for the grid, and
patching a past entry.

## Do

1. `GET /api/entries?day=<ms-timestamp>` (`app/api/entries/route.ts`): `getUserId()` →
   rate-limit (read) → return that local calendar day's entries newest-first (the client passes
   a timestamp inside the wanted day; compute day bounds server-side with `lib/time` helpers).
2. `GET /api/entries?rangeDays=10`: entries for the last 10 calendar days (for the grid),
   newest-first.
3. `PATCH /api/entries/[id]` (`app/api/entries/[id]/route.ts`): validate `entryPatchSchema` →
   `updateEntry` (which enforces user scoping and caps) → 404 when the entry isn't the user's,
   422 on cap violation, 200 with the updated entry otherwise.
4. Reuse the T012 route helper for auth/rate-limit/error mapping.
5. Integration tests in-process against PGlite with mocked auth: day query buckets correctly
   (an entry at 23:30 vs 00:30 across midnight), range query spans 10 days, newest-first
   ordering, PATCH edits own entry, PATCH on another user's entry → 404, oversized bullets
   patch → 422.

## Done when

`npm test` passes with the listed cases; routes contain no query logic (all in the stores).
