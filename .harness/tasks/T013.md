## Overview

The read/edit API for the vine: entries for a selected day, the 10-day range for the grid, and
patching a past entry.

## Do

1. `GET /api/entries?from=<ms>&to=<ms>` (`app/api/entries/route.ts`): `getUserId()` →
   rate-limit (read) → return the user's entries with `from` inside `[from, to)`,
   newest-first. TIMEZONE RULE: the server must never compute "which calendar day" — it runs
   in UTC while users live in local time. The CLIENT computes day bounds with `lib/time`
   (start/end of its local day, or of the local 10-day window for the grid) and passes
   explicit ms bounds; the server only range-queries. Validate: both params required, ints,
   `from < to`, span ≤ 31 days (400 otherwise).
3. `PATCH /api/entries/[id]` (`app/api/entries/[id]/route.ts`): validate `entryPatchSchema` →
   `updateEntry` (which enforces user scoping and caps) → 404 when the entry isn't the user's,
   422 on cap violation, 200 with the updated entry otherwise.
4. Reuse the T012 route helper for auth/rate-limit/error mapping.
5. Integration tests in-process against PGlite with mocked auth: range bounds are exclusive
   at `to` (an entry exactly at `to` is excluded, one at `from` included), newest-first
   ordering, span-too-large and missing-params → 400, PATCH edits own entry, PATCH on
   another user's entry → 404, oversized bullets patch → 422.

## Done when

`npm test` passes with the listed cases; routes contain no query logic (all in the stores).
