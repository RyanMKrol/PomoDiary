## Overview

One-time human provisioning of the external services the app builds against: the Vercel project
and the Neon (Postgres), Clerk (auth), and Upstash (Redis) marketplace integrations. Everything
downstream that touches real credentials depends on this. All three providers have free tiers
that cover personal-scale use (Neon: 0.5 GB / 100 compute-hours/mo; Clerk: 50K users; Upstash:
500K commands/mo); provision on the free plans.

## Do

1. From the repo root, link the project: `vercel link` (create a new Vercel project named
   `pomodiary` under your personal scope). Connect the GitHub repo `RyanMKrol/PomoDiary` to the
   Vercel project (Vercel dashboard → Project → Git) so pushes to `main` auto-deploy production
   and branch pushes get preview deploys.
2. Install the integrations (each may hand off to the browser to finish):
   - `vercel integration add neon` (creates the Postgres database; provisions `DATABASE_URL`)
   - `vercel integration add clerk` (provisions `CLERK_SECRET_KEY` + `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`)
   - `vercel integration add upstash` (Redis; provisions `KV_REST_API_URL` + `KV_REST_API_TOKEN`)
3. In the Vercel project env vars, add `NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in` and
   `NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up`.
4. Pull env locally: `vercel env pull .env.local --yes` (`.env.local` is gitignored; never commit it).
5. Update `.env.example` in the repo to list every variable name above (names only, no values),
   commit and push it.

## Done when

`vercel env pull` produces a `.env.local` containing `DATABASE_URL`, `CLERK_SECRET_KEY`,
`NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `KV_REST_API_URL`, `KV_REST_API_TOKEN`;
the GitHub repo is connected to the Vercel project; `.env.example` is committed. Then mark this
task done: `.harness/scripts/mark-done.sh T002`.
