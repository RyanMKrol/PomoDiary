## Overview

The client-side timer brain: one React hook that owns server-state reconciliation, the 1-second
tick, optimistic action dispatch, and debounced draft sync — the single source every UI
component reads.

## Do

Create `lib/client/useTimer.ts` (+ small helpers, all colocated-tested):

1. On mount, `GET /api/state`; hold `{ derived state, settings, hoursToday }` in React state.
2. A 1s interval recomputes the DERIVED view locally between server calls using the same rules
   as the server (`deriveNow` from `lib/timer` — import it; never duplicate the logic):
   remaining seconds while running, elapsed-away readout while away, and a local flip to chime
   when the wall clock crosses `hourStart + sessionMs` (then confirm with the server via a
   `ringNow`-equivalent read — the server derives chime independently, so a refresh agrees).
3. `dispatch(action)`: POST `/api/timer`, replace local state with the response; expose typed
   wrappers (`pause`, `resume`, `restart`, `ringNow`, `acknowledge`, `log`, `skip`, `awayStart`,
   `awayReturn`, `updateDraft`, `updateSettings`). On failure, refetch state (server wins).
4. Draft sync: `updateDraft` applies locally at once and debounces the `draftUpdate` POST
   (~800ms trailing) so typing bullets doesn't spam the API; flush pending drafts before `log`,
   `skip`, `awayStart`.
5. Expose `chimeEvents`: a subscribe hook (or callback prop) that fires exactly once per
   transition INTO chime (for T021 sound / T022 notifications).
6. Tests (jsdom + `vi.useFakeTimers`, fetch mocked): initial load populates state; tick counts
   down; crossing the boundary flips to chime once and fires the chime event once; dispatch
   posts and applies the response; draft updates debounce (one POST for rapid keystrokes) and
   flush before log; failed POST refetches.

## Done when

`npm test` passes with the fake-timer suite; the hook imports `deriveNow` from `lib/timer`
rather than reimplementing it; no component work in this task.
