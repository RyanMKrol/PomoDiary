## Overview

The server API for the timer: read reconstructed state, dispatch actions through the T008
engine, and read/update settings — thin routes that authenticate, rate-limit, validate, then
delegate to `lib/`.

## Do

1. `GET /api/state` (`app/api/state/route.ts`): `getUserId()` → rate-limit (read) → load
   timerState + settings from the stores (create `initialState(now)` + default settings on
   first touch) → return `deriveNow(...)` output (derived mode, remainingSeconds, chime span,
   drafts, phraseIdx) plus settings and today's entry count.
2. `POST /api/timer` (`app/api/timer/route.ts`): `getUserId()` → rate-limit (write) → parse
   body with `timerActionSchema` (400 on failure) → load state → run the T008 engine with
   `now = Date.now()` → persist the new state and insert any `entriesToInsert` (away backfill /
   log) via the stores → return the same derived-state shape as GET. Cap violations from the
   store (`CapError`) → 422 with a clear message; rate-limit block → 429 with `Retry-After`.
3. `GET/PATCH /api/settings`: PATCH validates `settingsPatchSchema`, upserts, returns the new
   settings.
4. Shared route helper in `lib/api/` (error → status mapping, JSON body parsing) so the three
   routes stay under ~40 lines each.
5. Integration tests (vitest, in-process — import the route handlers directly and call them
   with `Request` objects): mock `lib/api/auth` to return a fixed test user; use the PGlite db
   (inject via a test seam in the route helper or `vi.mock` the db module). Cover: first-touch
   creates state; a full happy cycle (ringNow → acknowledge → log) inserts an entry and resets
   drafts; invalid action body → 400; unauthenticated (mock throws) → 401; rate-limit mock
   block → 429; settings PATCH round-trips.

## Done when

`npm test` passes with the integration suite green against PGlite only (no real env);
`npm run build` passes; each route file delegates all logic to `lib/` (no business logic in
route bodies).
