## Overview

When someone deletes their account, their data must go too: a Clerk webhook endpoint that
receives `user.deleted` events (signature-verified) and purges every row the user owns from
Neon.

## Do

1. Add dep `svix` (Clerk signs webhooks with it).
2. `lib/db/purge.ts`: `purgeUser(db, userId)` deleting the user's rows from `entries`,
   `timerState`, and `userSettings` in one transaction; returns per-table counts.
3. `app/api/webhooks/clerk/route.ts` (POST):
   - Reads `CLERK_WEBHOOK_SIGNING_SECRET` lazily; if unset return 503 (endpoint dark until
     T032 configures it).
   - Verifies the svix signature headers against the raw body; invalid → 400. No Clerk
     session auth on this route (webhooks arrive unauthenticated — the signature IS the auth).
   - On `event.type === "user.deleted"`, call `purgeUser` with `event.data.id`; other event
     types → 200 no-op.
4. Middleware: the webhook path must be PUBLIC — add `/api/webhooks(.*)` to the
   public-routes matcher alongside sign-in/sign-up (it still can't be abused: the signature
   check gates it).
5. Update `.env.example` with `CLERK_WEBHOOK_SIGNING_SECRET` (name only). (The Clerk
   dashboard step that creates the webhook and the env var on Vercel lives in the T032
   deploy runbook.)
6. Tests: `purgeUser` on PGlite removes exactly the target user's rows across all three
   tables and leaves another user's intact; the route returns 503 without the secret, 400 on
   a bad signature (drive the real svix verify with a test secret and a tampered payload),
   200 + purge on a validly-signed `user.deleted` payload.

## Done when

`npm test` passes with the signature and purge suites; the webhook path is public in the
middleware while every other route stays protected; `.env.example` lists the new variable.
